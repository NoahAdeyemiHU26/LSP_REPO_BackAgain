# CRC Card Explanation

Library collaborates with Book because the Library's responsibilities, maintaining books, finding them, and coordinating borrowing and returning, require it to hold Book objects and ask them to change state, while Book's CRC card lists "None" as a collaborator because a Book only stores its own information and validates its own borrowing and returning, so it never needs to know about the Library that holds it. Keeping the dependency one-directional lets Book stay reusable (a standalone Book can be borrowed directly) and avoids a circular dependency between the two classes. Library enforces the three-book limit because the limit depends on how many books are borrowed across the whole collection, which is information a single Book cannot see; this matches the Library responsibility "enforce borrowing limit" on its CRC card. Book keeps only the per-book rule (an available book may be borrowed, a borrowed book may be returned), and Library delegates the actual state change to Book after checking the collection-level rule.
